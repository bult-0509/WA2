# 本机运行与操作说明

2026-09-04：第一阶段已运行。Next.js 16.3.4、NestJS 12.0.1、PostgreSQL 17.11；Node.js 24.13.0、npm 11.12.1。精确依赖以 package-lock.json 为准。

用户已批准从 PostgreSQL 官网指向的 EDB 下载 Windows x64 二进制到项目 .local，仅用于本机开发，不注册系统服务。下载、解压、初始化、启停与数据库往返验证已完成。未安装 Docker；新增缺失系统环境仍须先征询用户。

## 日常启停

本机已有依赖、数据库和开发账号，在项目根目录执行：

```powershell
& .\scripts\local-postgres.ps1 -Action start
npm.cmd run dev
```

官网：http://127.0.0.1:3100/ 。后台：http://127.0.0.1:3100/admin/login 。状态：http://127.0.0.1:3100/dev-status 。API：http://127.0.0.1:3101/api/v1 。数据库：127.0.0.1:5432。

请使用 127.0.0.1：写请求校验来源与 CSRF 请求头，localhost 是不同来源。工程暂固定本机端口；变更域名或端口需同步前后端来源、服务端 fetch 和检查脚本。

开发终端按 Ctrl+C 停止前后端。数据库单独执行：

```powershell
& .\scripts\local-postgres.ps1 -Action status
& .\scripts\local-postgres.ps1 -Action stop
```

停止前端不会清空数据。页面可访问但内容加载失败时，先检查数据库 status、API ready 和开发终端。脚本只管理本项目实例，不停止其他占用端口的服务。

## 数据与凭据

二进制在 .local/postgresql/pgsql，数据在 .local/postgresql/data，媒体在 .local/media。Windows 初始化程序在中文路径下遇到编码问题，因此 scripts/postgres-path.ps1 在 %LOCALAPPDATA%/WemoveRuntimeLinks 建立经目标检查的英文路径 junction；数据实体仍在本项目目录。不要移动正在运行的数据库目录。

数据库使用 SCRAM 和随机口令，应用角色 wemove 不是超级用户。连接信息与 MFA 加密 APP_KEY 在根目录 .env；数据库管理口令在 .local/postgresql/owner-password.txt。这些文件均已忽略提交。保留 APP_KEY，否则已有 MFA 密钥无法解密。

后台账号在 .local/dev-admin.json，包含 email、password、totp_secret 和认证器 URI。登录需要密码与动态验证码。本机执行：

```powershell
npm.cmd run admin:code
```

验证码约每 30 秒变化，成功用过的码不可再次登录。会话 30 分钟后过期，退出会撤销数据库会话。开发账号文件与验证码工具仅供本机使用；部署时另行实现账号发放、MFA 绑定与恢复，不携带开发凭据。

## 首次初始化与迁移

以下用于重新准备环境，当前本机无需重复初始化：

```powershell
npm.cmd ci
# 取得并解压用户批准的 PostgreSQL 二进制后：
& .\scripts\initialize-postgres.ps1
npm.cmd run db:setup
npm.cmd run dev
```

初始化脚本拒绝覆盖已有数据或 .env。db:setup 构建 API、执行迁移，在没有后台账号时创建随机开发账号，并在缺失时生成 APP_KEY。后续迁移执行 `npm.cmd run db:migrate`。迁移包含事务、锁及历史文件校验，不应修改已应用的 SQL。

业务表包括产品、独立默认 SKU、媒体、首页内容、后台身份、会话、询盘、限流及审计。种子只创建开发账号和首页占位文案，不创建冒充真实产品的数据。

来源：[PostgreSQL Windows 下载说明](https://www.postgresql.org/download/windows/)、[EDB 官方二进制页](https://www.enterprisedb.com/download-postgresql-binaries)。已取得 postgresql-17.11-3-windows-x64-binaries.zip，341325378 字节；postgres --version 返回 17.11。Compose 配置作为备用保留，未验证 Docker 运行。

## 操作流程

1. Products 创建产品，填写名称、slug 和 SKU，保存草稿。
2. 补全短描述、正文、至少三条特点、年龄、规格、安全说明、SEO 和真实主图。图片接受 PNG/JPEG/WebP，最大 2 MB，服务端解码并转成 WebP。
3. Publish product 后检查官网目录与详情。草稿及未发布媒体不能匿名访问；归档后离开目录，详情 URL 保留并提示停售。
4. 官网 Contact 填写联系信息并同意本机预览隐私说明，提交成功获得编号。重复同一请求不会重复建单。
5. Inquiries 查看并修改状态为 In progress 或 Resolved，保存内部备注；该操作不会发送邮件。
6. Homepage 编辑首页文案，Activity 查看操作。并发编辑版本冲突返回错误，避免覆盖刚保存的更新。

## 验证与限制

```powershell
npm.cmd run typecheck
# 先关闭开发进程再构建，构建后重新 npm run dev
npm.cmd run build
npm.cmd run check:runtime
npm.cmd run test:catalog
```

check:runtime 检查网页、API 存活和数据库就绪，任何失败返回非零状态。test:catalog 要求三项服务运行，使用隔离临时记录验证业务并清理自身数据库记录，结果在 tmp/verification/catalog-tests.json。验证证据与未测范围见 阶段一验证.md。
